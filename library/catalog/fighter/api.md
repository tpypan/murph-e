`ARCADE.fighter(config)` returns `{ init(api), update(api, dt), draw(api), inspect() }`.
Create the factory inside the game's `init`, then delegate update/draw. It owns round flow and calls runtime `win`/`gameOver`; do not add a second game loop or duplicate its HUD. `api.players` is authoritative: 1 gives CPU P2, 2 gives independent human P2. Both players share one arena. The round banner allows immediate movement, jumps and practice attacks; damage starts after the banner.

```js
let game;
function init(api) {
  game = ARCADE.fighter({ characterSelect: true, roster: ['batman', 'flash'], roundsToWin: 2, difficulty: 0.6 });
  game.init(api);
}
function update(api, dt) { game.update(api, dt); }
function draw(api) { game.draw(api); }
```

Supported config only:
- `roster`: exactly two character IDs, default `['batman','flash']`. These are the ONLY bundled identities. Batman has a pointed cowl/cape/emblem and batarang. Flash has a red mask/ear bolts/lightning emblem and speed dash. Original full animation sets are already bundled; do not regenerate or print them.
- `characterSelect`: boolean, default false for compatibility. The public demo enables it. Adds a player-controlled selection screen, then a 60-tick versus card and the existing 78-tick round intro. There is no selection timeout or automatic human confirmation.
- `selectableRoster`: with selection enabled, 1–8 unique character IDs; defaults to the unique IDs in `roster`. Every selectable ID must have a complete valid animation set, including characters not initially highlighted. `roster` sets initial cursors where those IDs are available; otherwise the cursor starts at the first choice. Both people may select the same identity; separate P1/P2 marks distinguish them without recoloring costumes.
- `cpuCharacter`: optional ID from `selectableRoster` for the 1P opponent. Otherwise the CPU uses the first available identity different from P1, or the same identity if only one is supplied. The opponent is explicitly labelled CPU. Player-two input never controls 1P selection.
- `selectionNames`: optional character-ID-to-display-label map (uppercase, first 10 characters). Used on selection and as the default combat label. This is presentation only, never new artwork or identity. The larger selected previews show these labels; small roster portraits abbreviate them when the roster grows.
- `names`: optional two display labels, at most 10 characters each. Changing a label does NOT change identity or artwork. Never claim a new character from a renamed existing sprite.
- `roundsToWin`: 1–5, default 2. `roundSeconds`: 15–120, default 60. `difficulty`: 0–1, default 0.6 (CPU decision cadence and visible-pose reaction delay). `sound`: false disables event sounds, default true.
- `specials`: optional two values `'projectile'` or `'dash'`. A custom character defaults to projectile; Flash is always dash.
- `moves`: optional per-move overrides for `light`, `heavy`, `sweep`, `airLight`, `airHeavy`, `special`, `dash`. Fields: startup/active/recovery/stun in frames, damage, push. Timing maps to the existing animation phases; animation and active collision remain synchronized. Defaults: jab 5/3/10, kick 11/5/21, sweep 9/5/20, air punch 4/6/10, air kick 8/6/14, projectile 13/5/22, dash 9/12/24. Hitbox geometry comes from sprite metadata.
- `stageColors`: `{sky: paletteIndex}`. `drawStageOverlay(api,{phase,round,ticks})`: optional extra drawing callback invoked after the built-in scene/HUD; keep essential fighter/HUD areas clear.
- `assets`: map of additional character IDs to complete pixel sets. Each set requires `frames:{id:{pixels:string[],anchor:{x,y},size:{w,h}}}` and `animations:{clip:{loop:boolean,frames:[{frame:id,duration:frames,anchor:{x,y},hitboxes:[{x,y,w,h,kind}],hurtboxes:[{x,y,w,h}]}]}}`. Feet are world origin, x points toward opponent, y is up-negative; hitboxes mirror with facing. Required clips: idle/walk/jump/crouch/light/airLight/airHeavy/heavy/sweep/special/dash/guard/crouchGuard/hurt/ko/victory. Attack clips require at least three steps: startup, active, then recovery. All hitboxes are tested against all hurtboxes; an empty hurtbox list is invulnerable. Every move/projectile still deals damage at most once per target. A clip-step anchor overrides its saved frame anchor for that step; omitting it uses the frame anchor. Supply actual distinct poses and a truthful identity. Unsupported IDs throw; they never silently become Batman.
- `debugHitboxes`: boolean, default false. `inspect()` returns a detached diagnostic state; it is for tests, not mutation hooks.

Selection controls: Left/Right cycles only that player's unlocked cursor. A locks that choice. B unlocks it, including during the versus card. 2P requires both independent confirmations; P1 cannot choose for P2. Each locked cursor stays put while the other person chooses. In 1P only the human locks; the CPU choice updates beside it. Initial held buttons cannot select or confirm, and a held confirmation cannot leak into a combat attack. Selected identities persist across rounds. A full `init`/runtime reset opens fresh selection with scores and locks cleared. `inspect().selection` exposes copied `available`, `cursors`, `locked`, `selected`, `humans` and `versusTicks`; `phase` is `select` or `versus` before `intro`. This metadata is diagnostic, not a way to bypass confirmation.

Actual controls: Left/Right move; holding away from opponent guards. Up jumps. Down crouches. A punches, Down+A sweeps. B kicks, Down+B spends 60 meter on special. A/B also attack in air. Standing guard blocks mid/high, crouch guard blocks mid/low; kick/air attacks are overhead. One strike per move, hitstop, buffered follow-up, light-to-heavy/special link. First to configured round wins. Never tell the user B is guard or A jumps.

Scoring: 10×damage to attacker, +50 linked-hit bonus, +500 round win; CPU does not increase P1 score. Complete rooftop foundation with optional character selection, not a multi-screen beat-em-up or faithful reproduction of proprietary Street Fighter code/art. For unsupported mechanics, implement the requested addition explicitly rather than claiming a config key does it.

The 1P CPU observes visible stance/action through a bounded 10–16 simulation-tick delay, then chooses at a 20–62-tick difficulty-dependent cadence. It never reads the human's input buttons. Standing guard invites a telegraphed low sweep; repeated crouching invites overheads or a jump attack; repeated high jabs can be ducked. Each choice still uses the ordinary authored startup, recovery, meter and collision rules. An attack chosen out of reach stays queued while approaching, rather than losing its only button edge or crouching motionless. Human-vs-human combat is unchanged. `inspect().fighters[i].ai` is null for a human and copied CPU planning/observation diagnostics otherwise; it is not a mutation API. Finite tests establish that permanent back-guard and tested one-button policies are answerable, not that human balance is solved.
# Source colors

Custom asset frames may include `palette`, an array of 1–16 `#RRGGBB` colors. The hex characters in `pixels` index this frame's palette; `.` is transparent, including when color 0 is opaque black. Every used index must exist. Without this field, the standard runtime palette applies. Frame palettes change rendering only; keep the documented anchors, move windows and hit/hurt geometry.

Frames may also include `layers: [{pixels, palette}]` (up to eight additional planes). Each layer must match the base frame dimensions and have its own 1–16-color palette. Draw order is base then layers. All planes share the selected anchor and flip; offsets are rejected. This preserves effects with more than 16 opaque colors without quantizing them. Layers are visual only and use the same clip timing and hit/hurt boxes. Invalid pixels, palettes, dimensions, timing, frame references or boxes are rejected at factory creation.

Projectile guard direction and knockback follow its incoming velocity even if the owner has turned around since firing. A blocked projectile does not push its distant owner backward.

Round-end animations continue while airborne fighters fall to the floor. Wide KO poses are kept inside the stage horizontally after damage resolution; active combat sprite placement and collision remain anchored to world positions.

# Character-specific projectiles

A custom character may include `projectile: {travel, impact?, bind?, speed, life, box, bindTicks?}`. Clip names reference that character's `animations` and frames. `travel` must loop; optional `impact` must not loop; optional `bind` may loop or hold its final frame. Every effect retains exact palettes, layers, duration and anchors. `speed` is pixels/tick, greater than 0 and at most 8; `life` is 1–180 ticks. `box:{x,y,w,h}` is a feet-style rectangle relative to the projectile origin with right-facing positive x; its offsets and size are bounded to 64 pixels. The hitbox covers the damaging head, not automatically the visual trail. The travelling effect is anchored independently from its owner and keeps its launch direction. Long trailing pixels reveal as the projectile travels, so they do not appear through the shooter at launch. Defaults without this metadata keep the original batarang.

For a configured projectile, `animations.special.frames[1]` must provide `projectileOrigin:{x,y}` inside the referenced right-facing pixel frame. This is a **frame-local emitter socket**, not feet-relative collision geometry. Launch uses socket minus the selected step/frame anchor, mirrored with facing. The second step remains the active phase; numerical move timing changes when the shot launches, not its registration.

Optional `bind` also requires integer `bindTicks` 1–90. On an unblocked, nonlethal grounded hit it draws the effect at the target's feet and prevents movement/jump/attack for that duration (ordinary hitstun can last longer). Air hits and guards never bind. Another actual damage event breaks the wrap; a 120-tick immunity prevents immediate rebinding. Hitstop pauses this simulation duration. Round end/reset clears the wrap. Projectile damage, meter cost and scoring use the documented `special` move; adding effect art does not silently grant a different attack. These are authored game rules, not inferred original behavior from source artwork.
